# Multichannel Cell Classification Methodology

Last reviewed against code on 2026-07-10.

This document describes the current classification method implemented in this
repository for the SUM159 Incucyte separate-image workflow. The final production
classification is generated by
`cellpose_pipeline/scripts/08_fuse_multichannel_classification.py` from
segmentation outputs of four image profiles: `Combined`, `Brightfield`, `Dead`,
and `Nuclei`.

The older single-image classifier,
`cellpose_pipeline/scripts/analysisi/02_classify_cell_states.py`, is retained as a legacy
RGB-only classifier and is described below for completeness. It is not used by
the current full fusion workflow when `SEGMENTATION_ONLY=1` and
`FORCE_CLASSIFICATION=0`.

## Objective

For each sample and time point, the workflow estimates:

- total cell count
- live cell count
- dead cell count
- dead fraction and live fraction
- per-cell state assignments
- a Combined-image QC overlay showing the final cell-state calls

The final counting unit is a `Combined` segmentation object. The `Combined`
mask acts as the anchor set of candidate cells. Evidence from `Dead`,
`Brightfield`, and `Nuclei` is used to correct or support the state assignment
of each `Combined` object.

## Source Code

Core files:

- `cellpose_pipeline/scripts/01_segment_images.py`
  runs Cellpose segmentation and, optionally, the legacy classifier at
  `cellpose_pipeline/scripts/analysisi/02_classify_cell_states.py`.
- `cellpose_pipeline/scripts/08_fuse_multichannel_classification.py`
  performs the current multichannel fusion classification.
- `cellpose_pipeline/scripts/analysisi/02_classify_cell_states.py`
  performs legacy RGB-only classification from one raw image and one mask.
- `cellpose_pipeline/hpc/run_multichannel_classification_fusion_array_task.sh`
  runs one fusion classification task for one normalized image key.
- `cellpose_pipeline/hpc/run_multichannel_classification_fusion_merge.sh`
  merges per-image fusion summaries.
- `cellpose_pipeline/hpc/submit_full_fusion_production.sh`
  is the current full production wrapper.

## Upstream Segmentation

Segmentation is performed by
`01_segment_images.py` in `--profile-mode auto`.
The profile is inferred from the parent folder name. Unsupported folders are
skipped when `--skip-unknown-profiles` is used.

For the current HPC array worker, each array task processes one raw image with:

```text
--profile-mode auto
--skip-unknown-profiles
--flat-profile-output
```

The full production wrapper sets:

```text
SEGMENTATION_ONLY=1
FORCE_CLASSIFICATION=0
```

Therefore `01_segment_images.py` does not call
`analysisi/02_classify_cell_states.py` in the production fusion workflow.

### Segmentation Profiles

The automatic segmentation profiles are hard-coded in
`01_segment_images.py`.

| Profile | Model | Diameter | Flow threshold | Cellprob threshold | Min size | Normalization | Preprocess | Postprocess |
|---|---:|---:|---:|---:|---:|---|---|---|
| Brightfield | `cpsam` | 25 | 0.0 | -1.75 | 20 | percentile 1.0 to 99.0 | percentile | none |
| Combined | `cpsam` | 25 | 0.0 | -1.75 | 20 | percentile 1.0 to 99.0 after RGB luma conversion | `rgb_luma` | none |
| Dead | `cpsam_v2` | 22 | 0.0 | -3.0 | 12 | fixed 7.6 to 55.0 | percentile | `dead_raw_signal` |
| Nuclei | `cpsam_v2` | 24 | 0.0 | -2.75 | 5 | percentile 0.5 to 99.9 | percentile | none |

Other shared defaults:

- `invert = False`
- `channel_axis = None`
- `normalize = False`
- `gamma = 1.0`
- `clahe_clip = 2.0`
- `clahe_tile = 16`
- `blur_sigma = 0.0`
- `background_sigma = 0.0`
- `tophat_kernel = 0`

Cellpose is called as:

```text
model.eval(
  prepared_image,
  channel_axis=<profile.channel_axis>,
  normalize=<profile.normalize>,
  diameter=<profile.diameter>,
  flow_threshold=<profile.flow_threshold>,
  cellprob_threshold=<profile.cellprob_threshold>,
  min_size=<profile.min_size>
)
```

### Image Preprocessing Before Cellpose

All auto profiles set `normalize=False` for the Cellpose call, so the pipeline
normalizes images before `model.eval()`.

For percentile normalization:

```text
low, high = percentile(image, [low_percentile, high_percentile])
prepared = clip((image - low) / (high - low), 0, 1)
```

For fixed normalization:

```text
prepared = clip((image - fixed_low_value) / (fixed_high_value - fixed_low_value), 0, 1)
```

For `Combined`, RGB is first converted to luma:

```text
luma = 0.299 * R + 0.587 * G + 0.114 * B
```

Then percentile normalization is applied.

### Dead Mask Postprocessing

The `Dead` profile applies `dead_raw_signal` postprocessing after Cellpose.
Each dead-channel object is kept only if it passes all raw-signal filters:

| Parameter | Value |
|---|---:|
| `filter_min_area` | 20 |
| `filter_max_area` | 2500 |
| `filter_max_aspect` | 4.0 |
| `filter_min_mean_delta` | 0.60 |
| `filter_min_p90_delta` | 2.00 |
| `filter_min_p90_abs` | 15.0 |
| `filter_min_snr` | 3.00 |
| `filter_bg_margin` | 14 px |

For each candidate dead object, local background is collected in a bounding-box
window expanded by `filter_bg_margin`. Background values are first taken from
pixels with dead-mask label 0. If fewer than 25 background pixels are available,
the code falls back to non-current-label pixels in the local window, then to the
whole image.

The local background scale is:

```text
bg_sigma = max(MAD(background) * 1.4826, 1e-6)
snr = (raw_p90 - bg_median) / bg_sigma
```

Objects passing the filters are relabeled consecutively and written as the
final Dead mask.

### High-Density Brightfield Adjustment

The workflow can call high-density fields after Nuclei segmentation. The
production DAG segments all Nuclei images first, creates `qc/density_calls.csv`,
then runs main segmentation.

For each Nuclei mask, the density metrics are:

- `nuclei_count`
- `nuclei_mask_fraction`
- `nuclei_area_median`
- `nuclei_median_nn_px`, the median nearest-neighbor distance between nuclei
  centroids

A key is called high density if any condition is true:

```text
nuclei_count >= 4000
nuclei_mask_fraction >= 0.22
nuclei_median_nn_px <= 16.0
```

Only the `Brightfield` profile has a high-density alternative:

| Profile | Model | Diameter | Flow threshold | Cellprob threshold | Min size | Normalization |
|---|---:|---:|---:|---:|---:|---|
| Brightfield high density | `cpsam` | 20 | 0.0 | -2.75 | 5 | percentile 1.0 to 99.0 |

This high-density adjustment affects the Brightfield mask used later as support
evidence in fusion classification.

## Current Fusion Classification

Fusion classification is performed by
`08_fuse_multichannel_classification.py`.

The method does not read outputs from `analysisi/02_classify_cell_states.py`. It
recomputes the RGB classification baseline from the `Combined` raw image and
`Combined` mask, then corrects it using `Dead`, `Brightfield`, and `Nuclei`
evidence.

### Fusion Parameters

Default `08_fuse_multichannel_classification.py` parameters:

| Parameter | Value | Meaning |
|---|---:|---|
| `overlay_alpha` | 0.55 | alpha used in QC state overlay |
| `bf_match_distance` | 35 px | maximum centroid distance from Combined object to Brightfield object |
| `nuclei_match_distance` | 35 px | maximum centroid distance from Combined object to Nuclei object |
| `dead_match_distance` | 25 px | maximum centroid distance from Dead object to Combined object |
| `min_dead_overlap_fraction` | 0.03 | minimum fraction of Dead object overlapping a Combined object |
| `min_combined_overlap_fraction` | 0.002 | minimum fraction of Combined object overlapped by a Dead object |
| `min_countable_area` | 35 px | Combined objects below this are final artifacts |
| `unsupported_artifact_max_area` | 80 px | small uncertain unsupported objects can become artifacts |
| `dead_min_area` | 20 px | minimum Dead evidence object area |
| `dead_max_area` | 2500 px | maximum Dead evidence object area |
| `dead_max_aspect` | 4.0 | maximum Dead evidence bounding-box aspect ratio |
| `dead_min_mean_delta` | 0.60 | minimum Dead object mean minus local background median |
| `dead_min_p90_delta` | 2.00 | minimum Dead object p90 minus local background median |
| `dead_min_p90_abs` | 15.0 | minimum Dead object raw p90 |
| `dead_min_snr` | 3.00 | minimum Dead object local SNR |
| `dead_bg_margin` | 14 px | background margin around Dead object bbox |

### Record Discovery

For each profile, `08_fuse_multichannel_classification.py` collects records from segmentation summaries and mask
files. It supports these output layouts:

```text
<run_root>/<profile>/segmentations/*_cp_masks.tif
<run_root>/<profile>/<run_name>/segmentations/*_cp_masks.tif
<run_root>/segmentations/<profile>/*_cp_masks.tif
<run_root>/segmentations/*_cp_masks.tif
```

Raw images are resolved from the segmentation summary `image_path` when
available. If the summary path is stale, `08_fuse_multichannel_classification.py` falls back to:

```text

```

Supported image suffixes:

```text

```

### Combined Anchor Objects

For each selected key, `08_fuse_multichannel_classification.py` requires:

- a `Combined` raw image
- a `Combined` segmentation mask

The `Combined` mask must have the same height and width as the raw image.
Each nonzero label in the `Combined` mask is treated as one candidate cell or
object.

The final state is assigned to each `Combined` label. Other channels do not
create additional final cells; they only provide support or dead evidence for
existing `Combined` labels.

### Combined RGB Feature Extraction

For each `Combined` mask label, the following features are extracted from the
raw RGB pixels inside that mask:

- `area`
- centroid coordinates
- bounding box
- median RGB values
- mean RGB values
- `r_frac`, `g_frac`, `b_frac`
- `log_b_over_r`
- `log_r_over_b`
- mean saturation, computed per pixel as `(max_channel - min_channel) / max_channel`
- `red_excess = r_frac - max(g_frac, b_frac)`
- `blue_excess = b_frac - max(r_frac, g_frac)`
- `purple_score = min(r_frac, b_frac) - g_frac`
- `red_blue_balance = 1 - abs(r_frac - b_frac)`

RGB fractions are calculated from median RGB:

```text
rgb_sum = median_r + median_g + median_b + 1e-9
r_frac = median_r / rgb_sum
g_frac = median_g / rgb_sum
b_frac = median_b / rgb_sum
```

Log ratios use a pseudocount of 1:

```text
log_b_over_r = log((median_b + 1) / (median_r + 1))
log_r_over_b = log((median_r + 1) / (median_b + 1))
```

### RGB Baseline Classification

The RGB baseline is deterministic and rule-based:

1. If `area < 35`, classify as:

```text
rgb_state = artifact
rgb_reason = area_lt_35
```

2. Else if `hsv_s_mean < 0.08`, classify as:

```text
rgb_state = uncertain
rgb_reason = low_saturation
```

3. Else if either blue/cyan rule is true, classify as dead:

```text
b_frac >= 0.40
blue_excess >= 0.055
log_b_over_r >= 0.25
```

or:

```text
median_b >= 175
b_frac >= 0.38
blue_excess >= 0.035
```

Then:

```text
rgb_state = dead
rgb_reason = blue_cyan_rule
```

4. Else if all strict purple conditions are true, classify as transitional:

```text
min(r_frac, b_frac) >= 0.34
g_frac <= 0.285
red_blue_balance >= 0.92
purple_score >= 0.055
hsv_s_mean >= 0.18
```

Then:

```text
rgb_state = transitional
rgb_reason = strict_purple_rule
```

5. Else if the red rule is true:

```text
r_frac >= 0.335
red_excess >= 0.015
```

Then:

```text
rgb_state = live
rgb_reason = red_rule
```

6. Else if both small low-saturation conditions are true:

```text
area < 80
hsv_s_mean < 0.16
```

Then:

```text
rgb_state = artifact
rgb_reason = small_low_saturation
```

7. Otherwise:

```text
rgb_state = uncertain
rgb_reason = no_confident_rule
```

### Brightfield Support

Brightfield support is based on centroid nearest-neighbor matching from each
`Combined` object to the nearest Brightfield mask object.

A `Combined` object is Brightfield-supported if:

```text
distance(Combined centroid, Brightfield centroid) <= 35 px
```

The output records:

- `bf_mask_id`
- `bf_distance`
- `bf_supported`

Brightfield support does not directly call a cell dead. It only supports the
existence of a countable non-dead cell when no Dead evidence is present.

### Nuclei Support

Nuclei support uses two signals:

1. Nearest-neighbor centroid matching from each `Combined` object to the nearest
   Nuclei mask object:

```text
distance(Combined centroid, Nuclei centroid) <= 35 px
```

2. Nuclei centroid inclusion. Each Nuclei centroid is rounded to the nearest
   pixel; if that pixel lies inside a `Combined` label, the count for that
   `Combined` label is incremented.

The output records:

- `nuclei_mask_id`
- `nuclei_distance`
- `nuclei_supported`
- `nuclei_centroids_inside`

As with Brightfield, Nuclei support does not directly call a cell dead. It
supports a countable non-dead cell when no Dead evidence is present.

### Dead Channel Evidence

Dead channel evidence is the strongest correction signal. It can override the
RGB baseline state and force the final state to `dead`.

For each key, `08_fuse_multichannel_classification.py` reads:

- Dead raw image
- Dead segmentation mask
- Combined segmentation mask

The Dead raw image and Dead mask must have the same shape as the Combined mask.
If the Dead raw image has three channels, it is converted to a scalar image by
averaging the first three channels.

For each Dead mask object:

1. Compute raw signal statistics inside the Dead object:

```text
raw_mean
raw_p90
raw_max
area
bbox aspect ratio
```

2. Compute local background from a window expanded by `dead_bg_margin = 14 px`.
Background values are selected from dead-mask label 0. If fewer than 25 pixels
are available, the code falls back to local non-current-label pixels and then to
the whole image.

3. Compute background and signal contrast:

```text
bg_median = median(background)
bg_sigma = max(MAD(background) * 1.4826, 1e-6)
mean_delta = raw_mean - bg_median
p90_delta = raw_p90 - bg_median
snr = (raw_p90 - bg_median) / bg_sigma
```

4. Keep the Dead object only if all Dead evidence filters pass:

```text
area >= 20
area <= 2500
aspect <= 4.0
mean_delta >= 0.60
p90_delta >= 2.00
raw_p90 >= 15.0
snr >= 3.00
```

5. Assign the kept Dead object to a `Combined` object.

Overlap assignment is preferred when the Dead object overlaps a Combined label
and either overlap condition is true:

```text
dead_overlap_fraction >= 0.03
combined_overlap_fraction >= 0.002
```

where:

```text
dead_overlap_fraction = overlap_pixels / dead_object_area
combined_overlap_fraction = overlap_pixels / combined_object_area
```

If overlap assignment fails, centroid assignment is used if:

```text
distance(Dead centroid, Combined centroid) <= 25 px
```

6. If more than one Dead object assigns to the same `Combined` object, the best
Dead evidence is selected by:

```text
score =
  snr
  + 0.25 * p90_delta
  + 10.0 * dead_overlap_fraction
  + 5.0 * combined_overlap_fraction
  - 0.02 * min(distance, 100.0)
```

The output records:

- `dead_mask_id`
- `dead_match_mode`, either `overlap` or `centroid`
- `dead_distance`
- `dead_overlap_pixels`
- `dead_overlap_fraction`
- `dead_combined_overlap_fraction`
- `dead_raw_mean`
- `dead_raw_p90`
- `dead_bg_median`
- `dead_p90_delta`
- `dead_snr`

### Final State Decision

The final state is assigned in this order:

1. Area filter:

```text
if combined_area < 35:
  final_state = artifact
  final_reason = area_below_countable_min
  confidence = high
```

2. Dead evidence override:

```text
if Dead evidence exists and rgb_state == dead:
  final_state = dead
  final_reason = rgb_dead_with_dead_channel_support
  confidence = high
```

```text
if Dead evidence exists and rgb_state != dead:
  final_state = dead
  final_reason = dead_channel_override
  confidence = high
```

3. Unsupported RGB artifact:

```text
if rgb_state == artifact
and not bf_supported
and not nuclei_supported:
  final_state = artifact
  final_reason = rgb_artifact_without_bf_or_nuclei_support
  confidence = medium
```

4. Unsupported small uncertain object:

```text
if rgb_state == uncertain
and not bf_supported
and not nuclei_supported
and nuclei_centroids_inside == 0
and combined_area <= 80:
  final_state = artifact
  final_reason = small_uncertain_without_bf_or_nuclei_support
  confidence = medium
```

5. Countable non-dead cell:

```text
if rgb_state == live
or bf_supported
or nuclei_supported
or nuclei_centroids_inside > 0:
  final_state = live
  final_reason = non_dead_countable_cell
  confidence = high if rgb_state == live else medium
```

6. Default non-dead Combined anchor:

```text
final_state = live
final_reason = non_dead_combined_anchor_default_live
confidence = low
```

Important interpretation: in the current fusion implementation, final states
are effectively `live`, `dead`, or `artifact`. The RGB baseline can label an
object as `transitional` or `uncertain`, and those labels are retained in
`rgb_state`, but the final `state` does not currently preserve
`transitional` or `uncertain` as final counting categories.

## Counting Definitions

For each image:

```text
total_masks = number of Combined labels processed
artifact_count = number of final artifact calls
total_cell_count = total_masks - artifact_count
live_cell_count = number of final live calls
dead_cell_count = number of final dead calls
dead_fraction = dead_cell_count / total_cell_count
live_fraction = live_cell_count / total_cell_count
```

Because the current final state space is live, dead, or artifact:

```text
total_cell_count = live_cell_count + dead_cell_count
```

unless future code changes add more final countable states.

## QC Overlay

The QC overlay is generated from the `Combined` raw RGB image and the final
state assigned to each `Combined` mask label.

The raw image is first normalized using 1st and 99th percentile scaling:

```text
base = clip((raw_rgb - p1) / (p99 - p1), 0, 1)
```

For each mask pixel with a final state, the overlay color is blended with:

```text
overlay_pixel = (1 - alpha) * base_pixel + alpha * state_color
alpha = 0.55
```

The saved PNG is side-by-side:

```text
[normalized Combined raw RGB | final state overlay]
```

State colors:

| State | RGB color | Display meaning |
|---|---:|---|
| `live` | `[1.0, 0.0, 0.0]` | red |
| `dead` | `[0.0, 0.25, 1.0]` | blue |
| `transitional` | `[0.65, 0.0, 0.85]` | purple, retained for compatibility but not currently used as a final fusion state |
| `artifact` | `[1.0, 0.9, 0.0]` | yellow |
| `uncertain` | `[0.55, 0.55, 0.55]` | gray, retained for compatibility but not currently used as a final fusion state |

## Legacy RGB-Only Classification in Script 17

`analysisi/02_classify_cell_states.py` takes:

```text
--raw-image
--mask-image
--image-id
--out-dir
```

It extracts per-mask RGB, HSV, Lab, shape, and bbox features using the provided
raw image and mask. Its rule-based state classifier uses the same core RGB
thresholds as the RGB baseline in `08_fuse_multichannel_classification.py`:

- area below 35 becomes artifact
- saturation below 0.08 becomes uncertain
- blue/cyan objects become dead
- strict purple objects become transitional
- red objects become live
- small low-saturation objects become artifact
- all remaining objects become uncertain

It writes:

```text
classification/features/<image_id>_per_cell_features.csv
classification/predictions/<image_id>_per_cell_predictions.csv
classification/predictions/<image_id>_summary.csv
classification/qc/label_overlays/<image_id>_state_overlay.png
```

This legacy output is not read by `08_fuse_multichannel_classification.py` and is not required for the current
multichannel fusion classification.

## Production DAG

The full production wrapper submits a dependency chain:

```text
Nuclei segmentation array
  -> density table job
  -> main segmentation array for Combined, Brightfield, Dead
  -> fusion classification array
  -> fusion summary merge
```

Each fusion classification array task processes exactly one normalized
`Combined` key:

```text
08_fuse_multichannel_classification.py
  --run-root <OUT_ROOT>
  --input-root <INPUT_ROOT>
```

## Methodological Notes

1. The final cell set is constrained by `Combined` segmentation. A cell not
   represented in the `Combined` mask cannot be added later by `Dead`,
   `Brightfield`, or `Nuclei`.

2. Dead calls are conservative but authoritative. A Dead object must pass raw
   signal filters and spatial assignment criteria before it can override a
   `Combined` object to final `dead`.

3. Brightfield and Nuclei are support channels. They can rescue weak or
   uncertain Combined RGB objects into final `live`, but they do not create
   final dead calls.

4. `total_cell_count` excludes final artifacts. It is the denominator for
   `dead_fraction` and `live_fraction`.

5. The method is deterministic and rule-based. It does not train or apply a
   statistical or neural classifier for final live/dead calls.

6. The full production fusion workflow does not call
   `analysisi/02_classify_cell_states.py`. It uses `01_segment_images.py` for
   segmentation only and `08_fuse_multichannel_classification.py` for final classification.
